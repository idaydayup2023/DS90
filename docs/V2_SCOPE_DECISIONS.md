# V2 功能取舍与 V3 对应

V3 不逐行搬运 V2，只围绕“字幕翻译”和“目录迁移”重建。以下清单用于防止旧入口或临时修复重新混入主程序。

## 保留

- 本地/FTP 媒体扫描与伴随文件迁移：统一收口到 `storage` trait 和同一计划执行器。
- 外部英文 SRT、容器文本字幕、PGS OCR、ASR 的来源顺序：统一经过内容评分、严格 SRT 和质量门。
- Ollama 与 OpenAI-compatible 翻译：模型只翻译 cue，不决定媒体类型或目标路径。
- 电影/剧集、1080p/4K 目标分区：画质证据与媒介类型完全分离。

## 重设计

- V2 多入口脚本改成唯一命令 `subtrans`，只有 `subtitles`、`migrate`、`doctor` 三个顶层命令。
- 迁移从“模型给结论后直接移动”改成规则证据、待确认队列、强类型逐路径覆盖、不可变计划和精确哈希批准。
- 完成状态从文件名推测改成输出哈希与 manifest 提交标记；迁移默认只接受有效 `ready`。
- 移动从一次性副作用改成租约、逐文件进度、目标唯一占用、原子发布、内容复核和重启恢复。
- 可选 AI 从运行时安装 Python/Torch 改成显式版本、可探测、可超时的外部 worker。

## 淘汰

- 剧情生成、泛化 IMDB 补全及与两条主线无直接关系的元数据工具。
- agents/MCP 包装、对话/PRD 临时材料及多个重复 CLI 入口。
- 运行时 pip 安装、隐式虚拟环境、未锁定的 OCR/ASR 下载逻辑。
- 让 LLM 生成 `S01E01`、推断电影/剧集或直接控制迁移目标的路径。

这些内容仍可在 `version2` 历史中查看，但不进入 V3 默认分支的运行树。

## 待验证或暂缓

- 群晖 DSM 原生执行：缺少具体 CPU、DSM/glibc 和实机故障测试，当前只作为存储端。
- 明文 FTP：保留可信内网兼容，发布门槛包括目标群晖实测；生产首选 SMB/NFS 挂载。
- 多集文件、日期型节目和动漫裸集数：规则证据不足，进入待确认并要求显式覆盖。
- Web UI、内置守护进程、跨端队列：没有证明对两条主线必要，暂不实现。

## 验收对应

- `Supergirl.2026.2160p...` 必须判电影，季/集为空；4K/HDR/HEVC 不得改变类型。
- 无完整季集证据不得自动迁移；所有 pending 必须能查看原因和覆盖键。
- 计划与配置/存储/内容任一变化后不可继续使用原批准哈希。
- 翻译失败不得发布 ready；单个文件失败不得阻断后续文件。
- 目标冲突、进程中断或重复执行不得覆盖未知内容或重复删除源文件。
